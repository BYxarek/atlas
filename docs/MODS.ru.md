# Моды ATLAS

Мод распространяется одним файлом **`.atlasmod`**. Один и тот же файл устанавливается в одиночную игру или в папку сетевых модов. Для LAN, VPS и PHP нет отдельных форматов и отдельных версий мода.

## Игрокам

В главном меню откройте **Моды → Установить мод…** и выберите `.atlasmod`. Включите одиночный мод, подтвердите доверие автору и перезапустите игру. Одиночные пакеты могут менять данные, карту, графику, звук, переводы, интерфейс и скрипты. Они выполняются с правами игры; установка сама по себе не включает мод.

Зависимости должны находиться выше зависимых модов. Поздний пакет заменяет одноимённые ресурсы раннего; автоматического объединения скриптов/JSON нет. Манифест задаёт `requires` и `conflicts`. После изменения содержимого одиночного пакета потребуется выключить и повторно включить его для одобрения.

Для сетевой игры есть отдельная папка **`user://network_mods/`**, её путь показан в меню. Кнопка **Установить сетевой мод…** копирует туда тот же `.atlasmod`. **Запустить с сетевыми модами** сохраняет профиль этой папки и предлагает перезапуск. **Вернуться к одиночным модам** возвращает прежний одиночный набор. Профили не смешиваются.

При входе в комнату с другим набором модов:

1. Игра показывает названия, версии и размер всех необходимых пакетов; игрок ещё не получает место в комнате.
2. Игрок выбирает **Установить все нужные моды** или отменяет вход. Без согласия скачивания и смены профиля нет.
3. Недостающие файлы скачиваются с хозяина LAN-комнаты, VPS или PHP-хостинга в `network_mods/cache/`. Уже имеющиеся точные копии используются повторно. Игра проверяет размер, SHA-256 всего файла, контрольную сумму PCK и манифест. Подмена версии, неправильный порядок, конфликты и недостающие зависимости отклоняются.
4. После установки нажмите **Перезапустить и подключиться**. На настольной системе игра перезапустится и повторит вход. На Android и при запуске из встроенного редактора закройте и снова откройте игру: профиль и адрес комнаты уже сохранены.

Для комнаты без модов будет предложено отключить текущий сетевой набор. Собственные файлы хозяина лежат в корне `network_mods`, скачанные — в подпапке `cache`, поэтому чужие версии не попадут в набор собственной комнаты. Загруженные версии остаются в кэше; они не активируются автоматически в одиночных кампаниях. Прерванные и некорректные загрузки не становятся установленными пакетами.

## Общие сетевые правила

Все три транспорта используют **одну схему: `changes`/`content` API 2 и прежний `network_balance` API 1** и один набор параметров из `assets/balance.json`: экономика, стартовые ресурсы, армии, цены, технологии, разведка, длительность операций, потери, вероятности и настройки ИИ. Godot и PHP применяют одинаковые значения; контрольная сумма профиля включает точные файлы и порядок.

Это общий исполняемый формат данных, а не разные моды для разных серверов. Нативные GDScript/сцены из одиночного PCK в сетевой игре не выполняются ни в LAN, ни на VPS, ни на PHP. Мод без корректных общих правил нельзя активировать как сетевой. API 2 поддерживает новые войска, здания, исследования, карты, сценарии, союзы, цели победы, события, медиа и панели. Полный справочник и редактор: https://byxarek.github.io/atlas/mods.ru.html#api2. Произвольный исполняемый код остаётся одиночным.

## Хозяину комнаты / администратору

- **LAN:** установите файлы в `network_mods`, нажмите **Запустить с сетевыми модами**, перезапустите игру и создайте лобби.
- **VPS:** положите те же `.atlasmod` в папку `ATLAS_MODS_DIR`. По умолчанию это `user://network_mods`; Docker использует `/data/network_mods`. Сервер читает её до загрузки симуляции. Перезапустите сервер после изменения файлов.
- **PHP:** положите те же файлы в `network_mods/` рядом с `api.php`. Обновите `mod_catalog.php`, `mods.php`, `service.php` и `simulation.php` вместе с клиентом. Нужен стандартный PHP 8.1+, расширения ZIP не требуются.

Один процесс сервера использует один фиксированный набор модов для своих комнат. Файлы папки читаются в порядке имён; например `01-base.atlasmod`, `02-addon.atlasmod`. Поставьте зависимости первыми. Для другого набора используйте другой экземпляр сервера. На клиентах точный порядок берётся из предложения сервера, а не из имён файлов кэша.

Не заменяйте файлы работающего сервера. Изменение набора создаёт отдельное пространство сохранений; прежние сохранения сохраняются и снова доступны при возврате прежних пакетов. Пакеты могут занимать до 64 MiB каждый, до 32 файлов и 128 MiB суммарно. Передача идёт блоками по 64 KiB с ограничением частоты, таймаутом и запретом произвольных путей. Для PHP скачивание идёт с того же адреса без перенаправлений. Никаких автоматических загрузок с адресов из манифеста нет.

Нужны одинаковые версии клиентской и серверной части: LAN/VPS wire **11**, PHP protocol **5**.

## Сборка

Пример [`examples/starter-economy`](../examples/starter-economy/mod.json) даёт 1000 стартовых монет. Собрать один распространяемый файл:

```powershell
& tools/godot-4.8-beta2/Godot_v4.8-beta2_win64_console.exe --headless --path . --script tools/build_mod.gd -- examples/starter-economy build/mods/starter-economy.atlasmod
```

Выходной файл должен быть новым; сборщик не перезаписывает существующий. В исходной папке нужны `mod.json` и `files/` с заменяемыми ресурсами относительно `res://`:

```text
my-mod/
  mod.json
  files/
    assets/balance.json
```

Сборщик поддерживает JSON, GDScript, текстовые сцены/ресурсы, шейдеры, TXT и CSV. Для скриптов/сцен удаляются `.remap`, чтобы исходники заменяли скомпилированные ресурсы экспортированной игры. Для графики/звука сначала экспортируйте нужные ресурсы и зависимости из Godot той же версии в `content.pck` рядом с манифестом; сборщик умеет упаковать и готовый PCK. Сейчас проект использует Godot 4.8-beta2. Не экспортируйте конфигурацию проекта, загрузчик и глобальные UID/class-кэши в PCK.

```json
{
  "api": 1,
  "id": "my-mod",
  "name": "My Mod",
  "version": "1.0.0",
  "game_version": "0.3.0",
  "description": "Description",
  "requires": [],
  "conflicts": []
}
```

Обязательны `api`, `id`, `name`, `version`, `game_version`. ID: 1–64 символа `a-z`, `0-9`, `_`, `-`. Версия игры проверяется точно. Если единственный исходный файл — `files/assets/balance.json`, сборщик автоматически добавляет его как `network_balance`: результат сразу подходит для всех трёх сетевых режимов. При упаковке готового PCK можно явно добавить `network_balance` в манифест. Это полный объект баланса с теми же ключами, размерами массивов и числовыми типами, что в штатном файле; некорректные вероятности, отрицательные значения и нулевые интервалы/делители отклоняются. Одиночная игра использует PCK, сетевая — исключительно эти общие правила.

Контейнер `.atlasmod`: 8 ASCII-байт `ATLASMOD`, 32-битная длина JSON в little-endian, UTF-8 JSON (до 64 KiB) с `pck_sha256`, затем PCK. Дополнительные библиотеки не нужны. Старые папки `mod.json` + `content.pck` остаются читаемыми для одиночных установок, но новый сборщик и файловый диалог используют один `.atlasmod`.

## Сохранения и восстановление

Одиночные кампании с модами сохраняются отдельно в `user://mod_saves/<fingerprint>/`. Сетевые сохранения также разделены по профилю; обычные кампании/комнаты не перезаписываются. Сохранение из другого профиля отклоняется до изменения текущей кампании. Для продолжения старой партии верните прежние файлы и порядок.

Безопасный запуск: `Atlas.exe -- --no-mods`. Он пропускает моды и сетевой профиль. Одиночный неудачный запуск также автоматически пропускает PCK при следующем старте. Чтобы навсегда сбросить сетевой профиль, выберите возврат к одиночным модам или переименуйте `user://network_boot.json`.

Проверки: `python tools/test_godot.py tests/test_mod_package.gd`, `python tools/test_godot.py tests/test_mods.gd`, `python tools/test_network_mods.py`. Последняя проверка передаёт один и тот же файл через LAN/VPS/PHP, перезапускает клиент отдельным процессом и проверяет вход и одинаковую симуляцию.

## API 2 и инструменты

Исходник может содержать только mod.json без files/: пример examples/frontier/mod.json. Сборка: tools/build_mod.gd SOURCE OUTPUT.atlasmod [DEPENDENCY.atlasmod ...]. Проверка всего упорядоченного набора: tools/mod_tool.gd validate MOD [MOD...]; inspect показывает итоговые данные и источники изменений; save-check сравнивает сетевой отпечаток с сохранением. В игре откройте Моды → Инструменты модов: инспектор, проверка пакета/сохранения и отдельная тестовая кампания. Изменённый набор не мигрирует старые сохранения автоматически.
