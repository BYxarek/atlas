# Разработка, баланс и эксплуатация

## Общие правила

Редактируемый источник цен, длительностей и коэффициентов — `assets/balance.json`.
`tools/prepare_php.gd` копирует его в `hosting/balance.json`; упаковка PHP отвергает устаревшую копию.
Число `version` описывает совместимость правил. При несовместимом изменении меняйте его и сетевые протоколы вместе.
Текущие протоколы: LAN/VPS 9, PHP 3. Клиент и сервер обновляются одним комплектом.
Старые сохранения без новых необязательных полей читаются; у старого матча характер бота назначается при первом ходе и затем сохраняется.

## Проверки и измерения

```powershell
./tools/build.ps1 -ChecksOnly
& tools/godot-4.8-beta2/Godot_v4.8-beta2_win64_console.exe --headless --path . --script tools/simulate_balance.gd -- 3 900
python tools/benchmark_php.py --workers 8 --requests 20 --rooms 4
python tests/test_storage_tools.py
```

Полный набор проверок запускается также workflow Game checks. Android-сборка и эмулятор в этом workflow не запускаются.
Проверки совпадения PHP/Godot включают три независимых начальных случайных состояния, 15 минут игрового времени,
четырёх ботов, отчёты и продолжение сохранения. Ошибка указывает первый путь поля и команду.
Для дробной силы допускается только относительная погрешность 1e-10 из-за сериализации floating point.

`build/balance-report.json` содержит стартовые страны, характеры ботов, первый захват, длительность,
территории, максимальное расширение, возврат территорий после потерь, армии, технологии и результаты боёв.
Это диагностическая выборка, а не доказательство равного баланса стран или стратегий.

`build/php-benchmark.json` измеряет конкурентные транзакции над временным хранилищем с настоящей симуляцией,
проверяет отсутствие потерянных записей. Это не HTTP-тест и не измерение тарифа провайдера.
На локальном Windows-хосте: 8 процессов, 4 комнаты, 160 транзакций — около 60 транзакций/с,
p95 ожидания общей блокировки около 125 мс. Каждая транзакция в этом сценарии продвигает все комнаты.
Разделение файлов по комнатам пока не сделано: сначала снимите измерения реальной нагрузки.

В `hosting/config.php` можно включить `'metrics' => true`: в закрытый PHP error log пишутся числовые
`lock_ms`, `transaction_ms`, `state_bytes`, `rooms`, а для API — `request_ms` и HTTP-статус.
Токены, имена игроков, команды и содержимое сохранений в эти метрики не попадают. По умолчанию метрики отключены.

## Обновление и откат PHP

1. Остановите API и cron в панели хостинга. Сохраните предыдущий архив программы и соответствующие клиенты.
2. Скопируйте `config.php` и каталог данных отдельно от архива программы.
3. Если доступен CLI, создайте согласованный снимок:
   `php storage.php backup /absolute/data /private/backups/before-update.php`.
   Инструмент использует ту же блокировку, что API, не перезаписывает существующий снимок и доступен только из CLI.
   Если CLI нет, используйте прежний способ скачивания файлов через FTP при остановленных API и cron.
4. Замените файлы программы, сохранив `config.php` и данные. Используйте клиент с PHP-протоколом 3.
5. Проверьте подключение, возвращение в старую комнату и готовность участников. Включите cron и API.
6. Для отката снова остановите API/cron, верните прежнюю программу и клиент, затем восстановите снимок:
   `php storage.php restore /absolute/data /private/backups/before-update.php`.
   Перед заменой сохраняется `before-restore.php`. Повреждённый JSON, неверная защитная строка и неизвестная
   версия хранилища отвергаются до замены состояния. Утилита проверяет оболочку хранилища, не совместимость всех игровых правил.

Снимки содержат приватные данные игроков: храните их вне публичной папки сайта.
Восстановление откатывает прогресс после даты снимка. Схемы сохранений PHP и VPS/LAN остаются раздельными.
Для VPS сохраняйте весь каталог данных при остановленном процессе и возвращайте согласованную пару сервер/клиент.
