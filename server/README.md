# Сервер ATLAS на VPS

Сервер запускает несколько независимых комнат, рассчитывает экономику, разведку, ботов и бои и сохраняет партии на VPS. Клиентам не требуется открывать порты. Центральный сервис ATLAS или общий аккаунт не нужны.

## Подготовка

- Linux VPS **x86_64/amd64** с публичным адресом и установленными Docker Engine и Docker Compose v2.
- Домен или поддомен, например `atlas.example.com`. Его DNS-запись **A** должна указывать на IPv4 VPS. Запись **AAAA** добавляйте только при работающем IPv6.
- В сетевом экране VPS и у провайдера разрешены входящие **TCP 80 и 443**. Эти порты должны быть свободны. Порт 24760 остаётся внутри Docker и наружу не публикуется.

Распакуйте исходники сервера, сохраняя структуру каталогов. Выполняйте команды в каталоге `server`:

```sh
cp .env.example .env
nano .env
```

Укажите свой домен и адрес электронной почты для уведомлений сертификатов:

```dotenv
ATLAS_DOMAIN=atlas.example.com
ACME_EMAIL=you@example.com
ATLAS_MAX_ROOMS=8
```

В `ATLAS_DOMAIN` вводится только имя домена, без `https://`, пути и порта. Допустимый лимит комнат — от 1 до 32; он включает сохранённые и неактивные комнаты. Вместимость каждой комнаты — до 176 игроков и ботов. Реальную вместимость VPS определяйте по нагрузке; измерений на разных тарифах пока нет.

## Запуск

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 atlas caddy
```

Первая сборка скачает Godot 4.8-beta2 с проверкой SHA-512 и подготовит серверный PCK. Caddy автоматически получает и продлевает HTTPS-сертификат. Для его первой выдачи должны уже работать DNS и доступ к TCP 80/443.

В клиенте **ATLAS 0.3.0** откройте **Сетевая игра**, укажите имя и `wss://atlas.example.com`, затем нажмите **Подключиться к VPS**. Создайте комнату либо войдите в существующую. Создатель комнаты становится администратором: добавляет ботов, удаляет участников и начинает матч после готовности всех. Кнопка **Скопировать приглашение** копирует адрес сервера и код комнаты; друг вводит адрес, затем код на странице сервера.

Список комнат публичный для подключившихся к этому серверу. Код комнаты — идентификатор, он не является паролем. Закрытых комнат и публичного каталога всех серверов в этой версии нет.

## Пауза, возвращение и управление

Обычный Esc открывает личное меню, серверный матч продолжает идти. **Вернуться всем в лобби** останавливает комнату. При отключении игрока комната также ставится на паузу; другие комнаты продолжают работать. Все участники должны вернуться и подтвердить готовность либо администратор удаляет отсутствующие места.

Если администратор выходит и в комнате остаётся другой подключённый человек, права передаются ему. Удалённый участник теряет территории, они становятся нейтральными. Администратор может удалить всю комнату из списка на сервере после выхода всех людей; это удаляет её сохранение и резервную копию.

После перезапуска VPS комнаты автоматически восстанавливаются в лобби. Игроки входят на тот же сервер и выбирают **Вернуться**. Деньги, войска, территории и операции сохраняются. Профиль определяется локальным `%APPDATA%/AtlasWorldGame/network_identity.cfg`: сохраните этот файл и не передавайте его другим. Для переноса своего места на другой компьютер перенесите файл при закрытой игре. Для каждого адреса VPS из локального секрета получается отдельный ключ, который передаётся внутри TLS; сам локальный секрет серверу не отправляется. Для возвращения используйте прежний адрес сервера: другое доменное имя или нестандартный порт образуют другой профиль. Локальные сохранения прежних LAN-партий остаются в прежнем режиме и автоматически на VPS не переносятся.

## Сохранения и резервная копия

Комнаты сохраняются при создании, изменении лобби, важных переходах и каждые 15 игровых секунд. Файлы `session_….json` и предыдущие версии `.json.bak` находятся в именованном Docker-томе `atlas-data`. При `docker compose down` тома сохраняются; **не используйте `down -v`, если хотите сохранить партии и сертификаты**.

Для согласованной резервной копии остановите игровой контейнер, скопируйте файлы и снова запустите его:

```sh
mkdir -p backups
docker compose stop atlas
docker compose cp atlas:/data/. ./backups/
rm -f ./backups/.stop
docker compose start atlas
```

Для восстановления при остановленном контейнере:

```sh
docker compose stop atlas
docker compose cp ./backups/. atlas:/data/
docker compose start atlas
```

Копия должна содержать только нужные `session_*.json` и `.json.bak`, без служебного файла `.stop`. Чтобы восстановить предыдущую версию повреждённой комнаты, сохраните повреждённый файл отдельно и замените его соответствующим `.json.bak`, убрав суффикс `.bak`. Повреждённые или несовместимые файлы не удаляются автоматически; причина выводится в лог.

`docker compose stop` посылает сигнал обработчику, который просит Godot сохранить комнаты и завершиться. На остановку отведено 20 секунд. При аварийном завершении VPS возможна потеря изменений после последнего успешного сохранения.

## Обновление и остановка

```sh
# Сначала сделайте резервную копию, затем обновите исходники.
docker compose up -d --build

# Остановить сервер с сохранением данных:
docker compose down
```

Клиент и сервер должны использовать совместимую версию сетевого протокола. Для этой версии используйте клиент 0.3.0 и исходники сервера из того же релиза. Это сервер для доверенной небольшой группы или сообщества: любой подключённый человек может создавать комнаты до установленного лимита. Платёжной системы и отдельной панели модератора нет.

## Разработка и диагностика

Без Docker можно запустить исходный проект Godot без окна:

```sh
ATLAS_DATA_DIR=/absolute/path/to/data ATLAS_MAX_ROOMS=8 \
  godot --headless --path /absolute/path/to/world-game -- --server
```

Он слушает обычный WebSocket на `ATLAS_PORT` (по умолчанию 24760). Для внешнего доступа ставьте его за TLS-прокси, как в Compose. Клиент разрешает открытый `ws://` только для `127.0.0.1` и `localhost`, например `ws://127.0.0.1:24760`; для внешних адресов нужен `wss://`. Установка неподтверждённых сертификатов и отключение проверки TLS не предусмотрены.

Если подключение не работает, проверьте DNS, доступность портов и `docker compose logs caddy`. Если контейнер `atlas` не готов — проверьте его лог, право записи в `/data`, значения переменных и совместимость сохранений. При уменьшении лимита ниже числа сохранённых комнат часть файлов может остаться незагруженной: верните прежний лимит или вручную перенесите ненужные файлы в резервную папку при остановленном сервере.

Основа конфигурации: [WebSocketMultiplayerPeer](https://docs.godotengine.org/en/stable/classes/class_websocketmultiplayerpeer.html), [серверный экспорт Godot](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_dedicated_servers.html), [автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https), [переменные Docker Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/).
