Mod documentation

From installing a package to authoring balance rules and hosting a room. Format, every parameter, examples and recovery in one guide.

Documentation for ATLAS 0.3.0 on main. The game, mod API and wire protocol have separate version numbers.

.atlasmodAPI 1 / 2Game 0.3.0LAN/VPS 11PHP 5

What you can change

One .atlasmod contains a manifest and a PCK. LAN, VPS and PHP use the same network package without rebuilding it for a transport. Solo play mounts its PCK before scenes and static data load. Network play applies validated API 2 changes/content and legacy API 1 network_balance; embedded native code is never executed in network mode.

AreaSoloLAN / VPS / PHP
Balance, armies, economy, pricesPCK / JSONAPI 2 changes / API 1 network_balance
Travel times, losses, probabilities, AI parametersPCK / JSONAPI 2 changes / API 1 network_balance
Map geometry, country count, neutral garrisonsAPI 2 contentAPI 2 content
Audio, translations, appearancePCK / API 2 contentAPI 2 content
New mechanics and arbitrary GDScriptReplace game scriptsNot supported

Internal game functions are not a stable plugin API. There is no built-in Lua, JavaScript, hook system, Steam Workshop or automatic GDScript-to-PHP conversion.

Installation and management

  1. Obtain an .atlasmod from a trusted author. Do not unpack the container.
  2. Open Mods → Install mod… and select the file. Installation copies its contents but does not enable it.
  3. Choose Enable, confirm trust and put dependencies earlier using Move up / Move down.
  4. Fully restart the game. “Active in this session” shows what is actually loaded, separately from the next-launch selection.

A solo PCK can execute code and access files with the game’s permissions. SHA-256 records approved contents, not author trustworthiness. Disable and re-enable a changed package to approve it. Installation never overwrites an existing mod: to update, disable dependents and the mod, restart, replace its directory and enable again. To uninstall, disable, restart and remove its directory. Back up campaigns separately first.

Joining a room and network profiles

  1. The host/server announces the exact ordered IDs, versions, sizes and SHA-256 package hashes.
  2. A different local profile opens Room mods required. You do not receive a lobby seat before matching the profile.
  3. Choose Install all required mods or cancel. Exact cached copies are reused; missing files come from this host/server.
  4. The game checks chunks, final size, container SHA-256, embedded PCK checksum, manifest and shared rules. Corrupt files are not activated.
  5. Choose Restart and connect. Desktop clients reconnect and repeat room admission. On Android or in the embedded editor, close and reopen the game: the profile and target have been saved.

A vanilla room offers to disable your current network set. Downloads stay in network_mods/cache/; host-selected packages live in the root of network_mods/. Other rooms’ cached versions do not automatically become your host set. Launch with network mods selects the root files; Return to solo mods restores solo mode after restarting.

Build your first mod

Download the SDK with three complete examples and extract it into a separate directory. It contains the builder, minimal Godot project, default balance and sources; no Python/npm installation is required. Use Godot 4.8-beta2 standard, not .NET. Run from the extracted SDK root and replace the executable path.

& "C:\Tools\Godot_v4.8-beta2_win64_console.exe" --headless --path . --script tools/build_mod.gd -- examples/starter-economy dist/starter-economy.atlasmod

The example gives a new faction 1000 coins. Install the one output file using the solo or network manager button. Check the treasury in a new campaign/room. Existing campaigns do not receive starting resources again. Output names must end in .atlasmod; existing outputs are never overwritten.

my-mod/
  mod.json
  files/
    assets/
      balance.json

files/ becomes the PCK’s res:// root. When its only file is files/assets/balance.json, the builder automatically includes a complete network_balance. The same output then works in solo and every network mode.

Formulas and units

power = Σ(units[i] × unit_weight[i] × (1 + (level[i] - 1) × technology_bonus))
effective = power × (naval_multiplier if overseas else 1)
research_price = technology_cost × current_technology_level
business_upgrade_price = business_cost × current_business_level
attacker_loss_fraction = clamp(defense / max(effective, 1) × attack_loss, attack_loss_min, attack_loss_max)

The default [35, 8, 4] army at [1, 1, 1] technologies has 75 strength; an overseas multiplier of 0.85 yields 63.75. Technology level 2 with a 0.25 bonus multiplies that branch by 1.25. A level-3 business with business_cost=25 costs 75 coins to upgrade and increases income from 3 to 4 coins per game second.

Equal effective strength is enough for an attacker victory. Unit losses round up and cannot exceed available troops. Combat uses armies/technologies at arrival. Seconds belong to the simulation: solo pause stops it; a personal multiplayer menu does not.

Dependencies, ordering and conflicts

{
  "requires": ["base-rules"],
  "conflicts": ["alternative-rules"]
}

The solo manager does not enable dependencies automatically: install/enable base-rules first, then its dependent. Invalid enable/reorder operations are rejected. A network offer must already contain the complete valid dependency set; the player downloads the required profile.

The last package replaces the whole network balance. If A changes start_coins and B changes naval_cost, B’s unchanged start_coins resets the starting treasury to its default. requires checks presence/order; it does not merge parameters. B must include A’s changes to preserve them. Declare conflicts when combining packages is not intended.

Host/server filenames determine order: 01-base.atlasmod, 02-addon.atlasmod. Client cache filenames use SHA-256; server profile order remains authoritative. An ID cannot appear twice. A version label never substitutes for exact file verification.

These replacements belong to solo PCKs. The atlas currently has 244 records; COUNTRY_COUNT, army arrays, neighbor references, geometry, saves and UI must agree. Changing country count requires related code changes, not just JSON. Preserve IDs when renaming and maintain reciprocal neighbors when changing borders. Enclosed microstates depend on enclave_hosts and reveal handling.

Minimal visual example: copy current src/world_map.gd to files/src/world_map.gd and change UNKNOWN to Color("586c83"). This replaces the entire script: verify picking, zoom and touch controls. Network mode ignores this code.

For new mechanics, copy the current complete script and preserve existing signals/contracts. Check callers, serialization and loading. There are no stable on_attack/on_tick hooks; adding those names does not register anything. Do not replace bootstrap, mods.gd or project configuration unless changing the game itself.

Solo customization examples

Work from complete files in the matching game source. The snippets below are edits, not standalone replacement files. The minimal SDK contains balance and the builder; obtain game scripts, maps and sounds from the matching game build.

Rename a country

In a full world.json copy, locate a record by id and edit name/english while keeping other fields. id is the country index; continent is a region string; center is [longitude, latitude]; rings contains outlines made of such pairs; neighbors lists neighbor IDs; sovereign is a sovereign ID; enclave_hosts lists surrounding countries for hidden microstates; dependencies lists related dependent territories. Links must reference existing IDs. Renaming does not require geometry changes.

{"id": 0, "name": "Новые Фиджи", "english": "New Fiji"}

Change a neutral army

In a full military.json copy, change only armies[target_id], for example armies[0] to [50, 5, 2]. Preserve array length, ID order, balance_version and other fields. Test in a new campaign and scout that country: existing saves hold their own armies. start_units in balance.json is different: it configures a new player/bot faction.

Change the theme

Copy src/main.gd to files/src/main.gd and change INK as below. This controls ordinary text color; also review MINT, MUTED and background colors in build_theme/style. Preserve readability, keyboard focus and phone text sizes.

const INK = Color("fff2d9")

Change an English label

In the complete assets/i18n/en.json, change the value for the Russian Settings key to Preferences. Russian UI uses original Russian strings; editing the English catalog does not rename Russian buttons.

{"Настройки": "Preferences"}

Change a fixed mechanic

Nuclear strike strength is not a network_balance field. A solo modification needs the full src/game.gd: change 0.5 to 0.4 in the arriving nuke operation. This leaves 40% of troops, rounded down. Update the result message (60% losses), translation and relevant checks. Preserve cancellation/refunding when the target is already owned. This does not become a network feature; a new shared rule requires schema and both simulation implementations to change.

countries[target].units[i] = floori(countries[target].units[i] * 0.4)

Graphics, audio and translations

The simple builder accepts only json, gd, tscn, tres, gdshader, txt, csv. Import PNG, SVG, OGG and other imported resources in Godot 4.8-beta2 using original game paths. Export selected changed resources and dependencies via Export PCK/ZIP → PCK, name it content.pck and put it beside mod.json. The same builder wraps an existing content.pck and ignores files/ in that case.

For a custom victory sound replace res://assets/audio/victory.ogg. Cue names are click, select, open, cancel, confirm, error, save, coins, upgrade, unlock, warning, all_clear, invasion, report, rocket_launch, rocket_loop, start, victory, defeat, campaign_win, campaign_lose, spy_send, spy_loop, naval_loop, army_loop, march, march_naval, battle, battle_naval, nuke, notification. army_loop/naval_loop/spy_loop/rocket_loop are looped by code. Merely adding music.ogg does not create a music player.

Translations replace the complete assets/i18n/en.json. Preserve Russian string keys and %s, %d, %.1f and %% formatting markers with the correct order/count. Country names use atlas name/english. A third language requires code and language-picker changes.

Include imported dependencies but avoid project.godot/project.binary, loader code and global UID/class caches. Test Windows and Android separately: texture imports and native extensions can be platform-dependent. PCK media/localization is not applied in network mode.

prepared-mod/
  mod.json
  content.pck

godot --headless --path . --script tools/build_mod.gd -- prepared-mod dist/prepared-mod.atlasmod

LAN host, VPS and PHP hosting

LAN

Install network .atlasmod files into the network_mods root using the manager. Choose “Launch with network mods”, restart and create a lobby. Other players connect via normal LAN/address flow and receive the host’s offer. Default game UDP port: 24760; LAN discovery: 24761.

VPS

Put the same files into ATLAS_MODS_DIR. Default: user://network_mods; Docker uses /data/network_mods. Start with the variables below. In Docker the directory must exist inside the mounted /data volume; optionally bind-mount a host network_mods directory at /data/network_mods:ro. Do not copy a client cache there.

export ATLAS_MODS_DIR=/srv/atlas/network_mods
export ATLAS_DATA_DIR=/srv/atlas/data
export ATLAS_PORT=24760
export ATLAS_MAX_ROOMS=8
godot --headless --main-pack AtlasServer.pck -- --server

These are environment variables: export them or configure a Linux service before running the command; in PowerShell use $env:NAME="value". Clients use wss:// with a valid certificate; plain ws:// is allowed only on localhost/127.0.0.1.

PHP

Create network_mods/ beside api.php and upload the same .atlasmod files. Deploy matching mod_catalog.php, mods.php, service.php and simulation.php from one server bundle. PHP 8.1+ needs JSON/Hash/PCRE/filesystem functions; no ZIP extension or Godot process is needed. The catalog is read on requests; mods.php serves only announced packages in chunks. Clients use HTTPS; HTTP is allowed only on localhost/127.0.0.1.

config.php controls data_dir, max_rooms (1–16), poll_ms (750–5000), lease_seconds (10–120), metrics and cron_key. These are hosting settings, not mod fields; do not put them in network_balance. data_dir must be writable without using 777. Keep cron_key private; CLI cron does not need a key.

Updates

One server instance uses one fixed profile for all rooms. Run separate instances for different sets. Stop the server/restrict access to PHP rooms, back up data, replace packages and update clients/server together. LAN/VPS wire=11; PHP protocol=5. Existing rooms do not migrate automatically after a profile change: restore their original profile to continue.

On Windows, user:// is normally %APPDATA%/AtlasWorldGame; the manager shows the exact path. Android uses private app storage with OS-dependent access; clearing/uninstalling removes campaigns and network identity.

Solo fingerprints include ordered IDs, versions and PCK SHA-256 hashes; network fingerprints use full .atlasmod SHA-256 hashes. Even changing a network container description changes its hash. Other-profile saves are rejected before mutating a campaign. Renaming an .atlasmod does not change its bytes but may change host order. Removing a mod does not migrate saves. Existing files remain, but restoring the exact set/order is required to read them.

Container and transfer limits

PartSizeMeaning
Magic8 bytesATLASMOD ASCII
Manifest length4 bytesuint32 little-endian
Manifest2…4 194 304 bytesUTF-8 JSON + pck_sha256

A file is at most 64 MiB (67,108,864 bytes). A network profile holds at most 32 packages and 128 MiB in total. Chunks are 65,536 bytes. Transfers check expected hash, offset and exact chunk size, then verify the complete file. Native serving is limited to 64 chunk requests/second/client and a 10-minute offer lifetime; clients wait up to 15 seconds per chunk. HTTP downloads use a 10-second timeout and no redirects.

The container is not ZIP: renaming a ZIP/PCK does not create a mod. The builder supplies the header, JSON and checksum. Do not manually “fix” a downloaded hash: the host checks exact bytes. Authors must rebuild and update the server profile when changing a version.

If your build has no Mods menu, it is an older client build, not a file-format error. This page documents development functionality; verify matching client/server builds and builder availability.

Testing and distributing a mod

  1. Build a new output file; verify ID, version and description.
  2. Test a solo mod in a new campaign, after save/load, during pause and at campaign end.
  3. For a network mod, connect a clean second client, cancel installation, then accept. Verify download, restart, admission and matching parameter values.
  4. Check vanilla mode, updated packages, dependencies/conflicts and restoration of an old profile/save. Test media/UI on target platforms and small screens.
  5. Distribute one .atlasmod with game version, dependency IDs and release notes. Exclude saves, network identity, local configuration and server secrets.
python tools/test_godot.py tests/test_mod_package.gd
python tools/test_godot.py tests/test_mods.gd
python tools/test_network_mods.py
./tools/build.ps1 -ChecksOnly

These checks run from the full game repository, not the minimal SDK. The network test transfers the same package in chunks over LAN/VPS/PHP, starts a new client process and verifies shared rules. All examples here are built from the current complete balance.json.

API 2: portable content

Use API 2 for new mods. Identity/version/dependency fields are unchanged; builders add pck_sha256. changes and content are optional. IDs use lowercase ASCII letters, digits, _ and -, up to 64 characters. Costs/income are integers; unknown content fields are rejected. Catalogs append in mod order; duplicate IDs fail validation. Later scenario, victory and map objects replace earlier ones; theme/assets/translations merge by key.

Open mod editor →

JSONDescription
changesPartial balance object. Specify only changed reference fields. Built-in troop arrays contain 3 values. Later mods win for overlapping fields; other fields remain. The inspector shows sources and overlaps.
content.units[]Up to 13 new branches (16 total). Required: id, name, cost, weight, recruit; defaults: start=0, requires=[]. Integer cost/weight/recruit ≥1, start ≥0. Built-in IDs: infantry, aircraft, navy; new entries follow them. requires lists technologies unlocking recruitment/upgrades.
content.buildings[]Up to 32 types. id, name, cost ≥1, income ≥0; requires=[]. Build only on owned territories. Next level costs cost × (level+1); income is income × level. Up to 1,000,000 levels; conquest preserves buildings.
content.technologies[]Up to 32 one-time technologies. id, name, cost ≥1; requires=[] must reference earlier technologies. Defaults: unit=infantry, bonus=0 (0..1), income=0. bonus adds to the selected branch strength multiplier; income adds global income per second. Available alongside regular upgrades.
content.map[]Complete map replacement: 3..512 contiguous IDs starting at 0. Fields: id, name (RU), english, continent, center:[longitude,latitude], rings:[polygon,...], neighbors:[ID,...], sovereign:ID, dependencies:[], enclave_hosts:[]. Coordinates ±180/±90; 3..2000 points/polygon, up to 64 polygons and 10,000 points/country. Borders must be mutual; references stay within the map. Empty enclave_hosts means a regular visible country. New neutral garrisons are [18,3,0,...] with one level-1 business.
content.scenarioOptional fields: name, default_home:ID, starts:{"ID":{coins,units,levels,owned:[ID],researches:[techID]}}, armies:{"ID":[garrison]}, alliances:[[ID,ID],...]. Troop arrays match the total branch count; levels ≥1. owned supplements the home country. Starting territories cannot overlap or include hidden microstates. Alliances are disjoint groups of home countries preventing mutual attacks; ownership remains separate.
content.victorytype: world (default world conquest), coins + amount ≥1, countries + countries:[ID], hold + countries:[ID] + seconds ≥1, time + seconds ≥1. hold requires uninterrupted ownership and resets on loss. Time is simulation time. Custom objectives replace world conquest; losing every territory still ends in defeat.
content.events[]Up to 128 events. Required: id, when, actions; defaults: once=true, cooldown=1 game second. Triggers: start, tick, country_captured, research_completed, building_built, mission_completed. Events run in order per faction. Up to 16 actions/event and 64 per trigger invocation, without recursion. Events beyond that budget wait for the next matching trigger.
events[].conditionsAll supplied conditions combine with AND: country_id (trigger country), elapsed_min, coins_min, owns:[ID], researches:[techID], flags:{key:value}, chance=100 (integer 0..100). start/research_completed use the home country; reconnaissance/conquest/construction use the target. Omit country_id for tick. Chance uses a separate saved deterministic generator shared by Godot/PHP.
events[].actions[]type and fields: add_coins {amount}; add_units {unit,amount}; show_message {text}; set_flag {key,value}; grant_research {technology}; capture_country/release_country {country_id}; win/lose require no extra fields. amount: integer ±1,000,000; unit defaults to infantry. Text ≤400 characters. Flags: bool or integer ±1,000,000, ≤128 distinct keys. Capture/research rewards do not recursively trigger events, award combat loot or charge research prices. No scripts or arbitrary filesystem access.
content.translations{"ru":{"source text":"translation"},"en":{...}}, up to 512 entries/locale, keys/values ≤1024 characters. Exact-key replacement; preserve %s/%d placeholders and newlines. Missing keys use normal game fallback. The settings navigation uses the keys Интерфейс, Экран and Звук. The menu uses Версия игры · %s and the update notice uses Доступно обновление · %s.
content.themeOptional HTML colors: ink (text), muted (secondary text), accent, ocean, unknown (unexplored land). Example: {"accent":"#f2cf70"}. Check contrast and visible focus.
content.assetsObject key → {mime,data}. flag:ID: PNG image/png up to 1024×1024; sound:CUE: WAV audio/wav replacing a standard cue. data is canonical base64. Up to 64 resources, 192 KiB decoded bytes/resource, 4 MiB total manifest. Resources travel inside the same .atlasmod; clients decode PNG/WAV, PHP does not execute them.
content.panels[]Up to 16 panels: id, title (≤160 characters), text (≤1024), action="". Displayed in the army card. action opens army, economy, countries or notifications. Text and standard buttons without HTML/JavaScript.

Extended workbench

Object forms

Choose an entry type, fill the form and save. Click an existing ID to edit it. Select technology dependencies from lists. IDs identify replacement entries; changing an ID creates a new entry. Source JSON remains available. Scenario forms configure starting troops, levels, garrisons, research, alliances and victory goals.

Map

Select a country on the map or list. Edit names, capital, sovereignty and dependencies. Saving neighbors repairs reverse links. Focus/zoom the selected island for precise editing. Move vertices by pointer or exact coordinates; insert/remove vertices, add islands and create rectangular countries. New maps start with three countries. Delete a country after removing scenario/event/media references; subsequent IDs are renumbered. Checks cover self-intersections, zero area, coordinates, mutual borders and geometric gaps between declared neighbors. Complex shared-border checks have a work limit and report a warning.

Event blocks

Choose events. When selects a trigger; If combines conditions with AND; actions run in order. Configure once/cooldown, flags and action order. Save the event first. In the sandbox, enter coins, elapsed time, RNG seed and additional state. The trace explains matches and skips: conditions, chance, once/cooldown, budget. This tests events, not the entire game.

Preview and diagnostics

Cards preview content, dependencies and theme; research connections appear as a tree; preview PNG and play WAV. Check separates errors and warnings. Errors include paths such as content.events[0].actions[1].unit. Click to open the entry. Errors block package export; warnings require author judgment. The SDK is the final full-profile validator.

Projects and history

Drafts autosave to this browser’s localStorage and can be restored explicitly. Undo/redo retain up to 20 states within an 8 MiB history budget. If storage is full, download .atlasproject. It includes manifest, raw source, resources/PCK, set packages, previous version and report. Importing API 2 .atlasmod preserves arbitrary PCK bytes as opaque data; the editor never executes or silently replaces them. Edit API 1 with source tools. Drafts do not sync between devices.

Compatibility

Load previous JSON or .atlasmod to compare fields. The report flags removed IDs, troop order, map, mod identity and game version changes. Even a description changes exact network bytes: structural comparison does not guarantee save compatibility. Network-save checking compares its mods value with the selected set fingerprint. Use the in-game checker for solo fingerprints. No automatic migration; source files remain intact.

Balance testing

Choose sessions (1..100), seconds (1..86400), bots (2..16), seed (1..2147483646), download the plan and export a package. Run the command below from the SDK or game source project with Godot available; pass --godot PATH if it is not on PATH. It uses the actual network simulation and shared AI. Starting countries rotate across runs; overlapping starts are skipped, insufficient countries stop the test. Reports include games, starting-country wins, income, first expansion time, development timelines, troop recruitment, final armies, research and small-sample/unused-troop warnings. Compare with a prior report; identical plans/seeds are repeatable. Existing reports are never overwritten. Import results into the workbench. Full games and batch combat do not execute in the browser.

Mod sets

Add .atlasmod files in the set section, order manually or topologically. Checks cover IDs, game versions, requires/conflicts, checksums and combined content. Exported .atlaspack includes exact original packages, order, versions, sizes and SHA-256. Lock files describe the set only. In game, Mods → Install mod set validates files, selects the network profile and requires restart. For VPS/PHP, unpack with the SDK command into a NEW directory and use numbered .atlasmod files as the root network_mods set. Existing destinations are never overwritten. Rooms keep one shared server profile and the normal required-mod installation offer.

content.ai

The object configures identical LAN/VPS/PHP bots. priorities lists up to 32 ordered rules. The first available action runs; otherwise normal game logic applies. action: research, construct, recruit, upgrade, business. id references a technology/building/troop; omitted for business. reserve preserves coins (0..100,000,000); max_level caps level/count (default 10). Normal requirements/prices apply. attack_ratio (0..2, default 1) multiplies the normal target-strength threshold. targets: weakest, income or nearest (land targets first). retreat_ratio (0..2, default 0) cancels an attack march when effective strength is below defense × ratio; operation costs are not refunded. AI rules apply to network bots, including balance tests.
